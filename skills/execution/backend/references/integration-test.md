# integration-test 阶段

后端接口实现完成后，根据用户指定范围或代码变更收敛接口测试；已有测试时执行，测试缺失时在人工确认后按仓库原生语言、框架和测试惯例生成，并输出正式报告。

## 范围

`scope` 可以是一个或多个：

- 接口：如 `POST /api/orders`
- 模块 / 包 / 工程：如 `order-service`、`tests/api/orders` 或项目原生模块标识
- 测试文件：如 `order.api.test.ts`、`test_orders.py`、`OrderApiTest.java` 或 `order_api_test.go`
- 测试名称：如 `creates an order`、`test_create_order` 或 `TestCreateOrder`

## 技术栈与测试层级

- 进入 `run` 或 `generate` 后必须读取 [integration-test-stack.md](./integration-test-stack.md)，根据仓库事实确定语言、框架、测试运行器、工作目录和命令。
- 不以文件扩展名单独判定技术栈，不把自己熟悉的测试框架当成项目默认值。
- 区分并如实报告测试层级：使用 fake / mock 隔离业务或外部依赖的是「接口入口测试」；连接真实进程内组件、数据库或消息设施的才标为「组件集成测试」；穿过完整部署链路的标为「端到端测试」。
- 用户口语中的「集成测试」不自动改变实际测试层级；报告以测试设施和断言事实为准。

## 环境与副作用门禁

- **本地隔离环境**：进程内 fake / mock、临时容器、临时数据库或明确按用例隔离且可自动回收的资源。范围和命令明确后可以执行。
- **共享测试环境**：daily、test、staging 或其他多人共用的数据库、缓存、消息设施、对象存储与外部服务。执行前必须披露目标环境、数据作用域、写入 / 更新 / 删除、副作用、清理方式、失败后的恢复方式和可复核的授权记录，随后停止等待用户明确确认。
- **生产或环境不明**：停止执行，不用“只跑测试”“接口只返回 200”或命令名称推定安全。
- 用户指定测试 scope 只授权测试范围，不自动授权共享环境数据写入、删除、批量操作、消息发送或外部调用。
- 清理动作涉及共享数据删除、批量回滚或基础设施重置时，必须再次列出精确目标并取得单独授权；不能把清理权限隐含在测试执行确认中。

## 用户指定范围

- 用户指定的接口、包、测试文件或测试名称优先级最高。
- 只能把用户目标解析为真实存在的代码、测试与项目命令，不得自行扩大成全仓测试。
- 指定目标不存在、相互冲突或无法唯一映射时，先说明歧义并等待用户补充。
- `run` 范围明确且属于本地隔离环境时可以执行，不得额外加入“可能相关”的测试；共享环境仍必须经过副作用门禁。
- `generate` 即使范围明确，也必须先展示测试文件和用例计划并等待确认；用户指定 scope 不等于授权写文件。

## 用户未指定范围

- 只能先读取 Git 变更、路由 / RPC 入口、业务组件、数据访问组件和已有测试，生成候选清单。
- 候选清单必须说明代码变更、受影响接口、测试目标、拟执行或生成内容、命令、理由和置信度。
- 展示候选清单后必须暂停；只有得到明确确认后才能执行或生成。
- “看起来可以”“应该没问题”等含糊表达不视为执行或写入确认。
- 确认期间代码发生变化时必须重新识别范围并再次确认。

## 通用原则

- 使用中文输出，代码事实优先，不根据文件名或接口名称臆造测试关系。
- 优先使用仓库已有 Makefile、Taskfile、脚本、CI 配置和测试说明；不得直接假定 runner 的全量命令是正确入口。
- `generate` 优先复用同模块已有测试结构、fake / mock、fixture、请求构造和断言风格。
- 不自动安装依赖，不自动启动、停止或重置共享基础设施，不执行数据库迁移或共享数据清理。
- 测试环境不明确或疑似生产环境时停止执行；共享测试环境按“环境与副作用门禁”披露并等待单独确认。
- 不自动重试失败测试；用户要求重试时，报告保留首次结果和重试结果。
- Token、Cookie、密码、手机号和其他敏感数据必须脱敏。
- HTTP 200 或退出码为 0 只说明相应断言通过，不得推定未被断言的数据库、缓存或消息结果已经验证。

## 结果口径

- `通过`：测试实际执行并通过全部已有断言。
- `失败`：测试实际执行但至少一个断言失败；报告必须标记“待转遗留问题”。
- `阻塞`：编译、环境、依赖、认证或基础设施问题导致目标测试未进入有效执行。
- `跳过`：最终确认范围内的测试被测试框架明确报告 skip。
- 总数必须满足：`总数 = 通过数 + 失败数 + 阻塞数 + 跳过数`。
- 测试框架存在套件、嵌套用例或子测试时，优先统计最终叶子测试，避免重复计算父子结果。
- 用户在确认阶段删除的候选不属于最终执行范围，不计入总数或跳过数。

## 交付约束

- 报告路径必须由用户确认；已有同名文件时不得直接覆盖。
- `generate` 的新增或修改文件必须逐个列入确认计划；已有测试文件不得直接覆盖。
- 报告必须记录范围来源、Git 比较基准、语言 / 框架 / 测试运行器、测试层级、环境隔离等级、数据影响、清理 / 恢复方式、授权记录、最终确认范围、实际命令和执行时间。
- 失败用例必须保留实际结果和必要日志摘要，并标记“待转遗留问题”。
- 截图、Postman/Apipost 调试结果、单元测试覆盖率和外部附件不属于本阶段交付物。
