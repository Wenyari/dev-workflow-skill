# PRD Review

## 对齐边诊断

| 项 | 值 |
|---|---|
| 服务对齐边 | PM↔前端、PM↔后端 |
| 现状分级 | 结构性不健康 |
| AI 形态 | 补契约工具 |
| 主战场 | 需求评审前 |

## 这个 skill 解决什么问题

按固定检查表识别 PRD 中会阻塞或显著影响技术方案的缺失、边界、风险和冲突，并输出可审核的问题清单。

## 前置产物

| 产物 | 来源 | 是否必需 |
|---|---|---|
| PRD 全文 | 用户、本地文件或共享文档读取工具 | 必需 |
| 相关接口、现状代码或产品规范 | 用户、仓库或 `tools/product-design-specs/` | 按评审项需要 |

## 输出产物

| 产物 | 位置 | 下游消费者 |
|---|---|---|
| `prd-review.md` 或对话内问题清单 | 用户确认的位置或当前对话 | 前端/后端技术方案负责人、产品 |

## 下一步

- 无阻塞项 → 将 PRD 与评审结论交给前端或后端执行流程生成技术方案。
- 存在阻塞项 → 由产品补充或确认后重新评审。
- 严重但不阻塞的问题 → 在后续 `page-tech.md` 或 `api-tech.md` 的风险与待确认项中保留。

## 明确不做

- 不修改 PRD：Review 只提出问题和证据，产品仍是需求内容决策者。
- 不直接生成前端或后端技术方案：评审产物只作为后续流程输入。
- 不做 PRD↔UI 逐页一致性检查：该能力属于 `prd-ui-check`。
- 不评价业务价值或排期优先级：本 skill 只检查可开发性、边界和技术冲突。

## 详细规则

执行时必须完整读取：

- [references/prd-review.md](./references/prd-review.md)
- [templates/prd-review.md](./templates/prd-review.md)

L0/L1 默认不强制运行；L2 推荐运行；L3 必须在技术方案前完成并落 `prd-review.md`。

问题分级、检查维度和输出格式以 reference 与模板为准。多个下游流程使用同一份报告时，只通过报告传递结论，不让 Review skill 修改执行层文件。
